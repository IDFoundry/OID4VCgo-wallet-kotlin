HttpWalletProvider

class HttpWalletProvider : WalletProvider(source)

A WalletProvider over the Wallet Provider HTTP protocol, version 1, that OID4VCgo's walletprovider.Provider.Handler serves (WALLET_PROVIDER.md), with Android Key Attestation (android-key) as its evidence:

  • The installation registers once, at its first Wallet Attestation: it makes a registration key in a key store of its own (registrationKeyStore) over a registration challenge, registers it with its attestation chain (POST /v1/instances), and keeps the instance ID and the key's ID in its InstanceRegistry. The registration key signs every later request (Wallet-Provider-Request); no attestation names it. If the registration or its key is lost, the next Wallet Attestation registers again, with a new key.

  • attestationChallenge gets an instance challenge for each instance key — the wallet makes one per issuance, in its own key store — and a holder challenge the holder keys of one Key Attestation share, so AndroidKeystoreKeyStore makes each key over it.

  • walletAttestation asks for a Wallet Attestation for the instance key (instance_key). While it remembers the instance challenge the key's attestation certificate carries, it sends that challenge and the key's chain: the provider needs them the first time it's asked for the key, and ignores them once it has recorded it. Later — at a refresh, once the challenge has expired — it sends the key alone.

  • keyAttestation asks for a Key Attestation over the holder keys, with their chains, for the issuance of its instance key (KeyAttestationRequest.instanceKey), which a Wallet Attestation recorded.

It sends nothing but to its base URL, over https, following no redirect, with its timeout for connecting and for reading, and reads at most 256 KiB of an answer. It checks a Wallet Attestation is for the client and the instance key, and a Key Attestation is over the nonce sent and attests only keys sent; their signatures are the issuer's to verify.

Failures reach the wallet as WalletExceptions: one the network or the provider's availability caused (no connection, a timeout, HTTP 5xx or 429, a challenge that expired before it was used) as WalletException.Code.network, which may be retried; a refusal (WalletProviderRefusedException) as WalletException.Code.platform, its message naming the protocol's error code. On instance_revoked, it forgets the registration and deletes its registration key: the next Wallet Attestation registers the installation again. The revoked instance's instance keys stay its own (instance_key_registered), so a credential whose refresh needs one must be received again. On instance_not_active (suspended) it keeps the registration: tell the holder, as the provider may resume it. A signed request refused as invalid_signed_request isn't retried: check the device's clock, and that the provider still knows the instance.

Keys are matched to the challenges they were made over by the challenge's bytes in their attestation certificate. Holder keys made while no Key Attestation has used the current holder challenge share it, so of two issuances making holder keys at once only the first Key Attestation can use it: the other fails as WalletException.Code.network, and succeeds when tried again.

The installation registers once, and the challenges handed out are remembered, for every HttpWalletProvider over the same FileInstanceRegistry file (or the same InMemoryInstanceRegistry) in the process, so a wallet rebuilt mid-issuance with a new provider carries on with the old one's. Over a registry of its own type, a provider shares them with no other: keep one provider for it.

suspend fun sweepOrphanedRegistrationKeys(): Int

Deletes every key in the registration key store but the kept registration's, and returns how many it deleted: the keys of registrations that never finished, as when the app's process ended in the middle of one, which nothing else deletes. Call it at launch. It takes its turn with registrations over the same registry, so it never deletes the key of one in progress.
