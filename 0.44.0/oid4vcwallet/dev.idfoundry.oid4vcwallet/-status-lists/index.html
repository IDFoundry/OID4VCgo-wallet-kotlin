anyAge

val anyAge: Boolean

Accepts a status or identifier list of any age, until its exp, in place of maxAgeSeconds: set it only where your issuers' lists expire soon after they're signed, or where whoever serves them is trusted not to serve an old one. It can't be set with maxAgeSeconds (from OID4VCWallet 0.44.0).

cacheDir
Link copied to clipboard
val cacheDir: String?

Where the lists verified are kept across launches: a launch then asks each list's server whether the list it kept is current, a 304 Not Modified rather than the list, and never uses one the server hasn't confirmed. The lists are authenticated with a key the library makes, wrapped by an Android Keystore key, so one anyone else wrote to the directory is dropped. Null, the default, keeps them in oid4vcwallet-status-lists in the app's context.cacheDir (found from java.io.tmpdir, and used only when that is the app's own cache directory), or in memory only when it isn't, or that key can't be had; an absolute path, the app's own, keeps them there; empty keeps them in memory only. The directory isn't encrypted beyond the app's storage: it shows whoever can read it which status lists are checked (their URIs, so the issuers of the credentials, not which entries), the lists themselves, and when each was last checked.

cacheMaxAgeSeconds
Link copied to clipboard
val cacheMaxAgeSeconds: Long

How long a status or identifier list fetched is used before it's revalidated, in seconds: 0 means 5 minutes, at most a day, and never past the list's own ttl or exp. Longer means fewer requests, and a revocation seen that much later. It bounds nothing a list's server answers with: for that, see maxAgeSeconds.

maxAgeSeconds
Link copied to clipboard
val maxAgeSeconds: Long

How long ago a status or identifier list may have been signed, in seconds, at most a year; 0 sets no bound. A list signed before a revocation stays valid until its exp, which an issuer may put months ahead, so anyone who can serve bytes at the list's URI (a CDN, a mirror, a former owner of the domain) could replay it until then; with this, only for this long after the revocation. A list older, fetched or kept, fails the check, so set it above the longest interval your issuers sign their lists at: 86_400, a day, for issuers that sign them at least daily. Outside development, a Wallet with issuer roots and a ProximityReader with ProximityReaderConfiguration.StatusCheck.CHECK need it, or anyAge; without either, the constructor throws invalidInput (from OID4VCWallet 0.44.0).
