development
Link copied to clipboard
val development: Development?

Relaxes what production requires, for a wallet talking to services on a development machine; null, the default, is production. Never ship an app with it set. It lets issuers, Authorization Servers, Verifiers and status lists be on loopback addresses, over http there too; makes requests through an ordinary HTTPS client, which reaches private network addresses, instead of the hardened one (trusting Development.roots too, when set); requires no revocation choice for a trust role, so a role in neither Revocation.roles nor Revocation.declined is checked for nothing; requires no bound on a status list's age (StatusLists.maxAgeSeconds or StatusLists.anyAge); skips the check that different roles' roots share no anchor; and skips the production checks on receiving credentials: durable stores and keys, and the random source. Refused (invalid_input) unless the app called OID4VC.allowDevelopment, from a debuggable build only.
