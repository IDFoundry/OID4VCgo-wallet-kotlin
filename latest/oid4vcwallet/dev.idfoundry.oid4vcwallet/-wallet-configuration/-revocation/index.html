crlIssuers
Link copied to clipboard
val crlIssuers: String

PEM certificates of the CAs that issued certificates pinned in the roots (a leaf in VerifierTrust.roots, say), for a role in roles: a pinned certificate is checked against its CA's CRL, verified with the CA's certificate from here. They aren't trust anchors. Without its CA here, a pinned certificate that isn't self-signed is refused.

crls
Link copied to clipboard
val crls: String

PEM X509 CRL blocks: the Certificate Revocation Lists the roles in roles are checked against. Replace them at runtime with Wallet.setCRLs as they expire.

declined
Link copied to clipboard
val declined: List<WalletConfiguration.RevocationRole>

The trust roles that decline checking revocation, as an explicit choice: only where something else stands in for it, such as certificates too short-lived to be worth revoking. A role can't be in both this and roles.

distributionPointsFromRoots

val distributionPointsFromRoots: Boolean

Also fetches, in Wallet.refreshCRLs, the distribution point each self-signed CA certificate names for its own list (as an IACA does), among crlIssuers and the roots of the roles in roles.

requireHTTPS
Link copied to clipboard
val requireHTTPS: Boolean

Refuses plain http distribution points, and leaves them out of distributionPointsFromRoots.

roles
Link copied to clipboard
val roles: List<WalletConfiguration.RevocationRole>

The trust roles whose certificate chains must pass a CRL check against crls. A role listed fails closed for any CA it has no current CRL from, until Wallet.setCRLs supplies one. Outside WalletConfiguration.development, each role whose roots are set must be listed here or in declined, or the wallet isn't made (invalid_input).
